Phase 1 Setup & Prerequisites

Before building the sync pipeline, configure all three tools and set up your project structure. Complete every step here before proceeding.

1.1

Prepare your Figma file

Enable Dev Mode · Organize Variables · Standardize naming

▼

Enable Dev Mode — open your Figma file, click the Figma logo (top-left), and select Enable Dev Mode. This unlocks the Variables API and code inspection.

Organize Variables as tokens. Create variable collections for each category:

  • Color — brand, semantic, and state colors
  • Spacing — base-4 or base-8 scale (4, 8, 12, 16, 24, 32…)
  • Typography — font sizes, weights, line heights
  • Radius — border radius values
  • Shadow — elevation levels

Standardize component naming using the slash convention so Claude can map them to file paths:

Button/Primary/Default Button/Primary/Hover Button/Primary/Disabled Input/Text/Default Input/Text/Error

Get your Figma credentials. Go to Account Settings → Personal Access Tokens. Create a token with Read scope. Copy your FILE_KEY from the URL:

https://www.figma.com/design/FILE_KEY/Your-File-Name ^^^^^^^^^^^ Copy this part
💡 Tip

Store the FILE_KEY and token in a password manager now. You'll need them in every script in this guide.

1.2

Create the repository structure

Scaffold folders · Install all dependencies

▼

Create this folder layout in your project root:

my-design-system/ ├── src/ │ └── components/ # Generated React components ├── tokens/ │ ├── figma-raw.json # Raw export from Figma API │ └── tokens.json # Style Dictionary format ├── scripts/ │ ├── export-tokens.js │ ├── generate-component.js │ └── sync-to-figma.js ├── figma-plugin/ │ ├── manifest.json │ └── code.ts └── .github/workflows/ └── design-sync.yml

Then install all required packages:

npm install @anthropic-ai/sdk style-dictionary ts-morph \ @octokit/rest @figma/plugin-typings npm install -D @storybook/addon-designs chromatic
1.3

Configure environment variables

Store credentials · Add GitHub Secrets

▼

Create .env.local at the project root and add all five secrets:

FIGMA_TOKEN=figd_xxxxxxxxxxxxxxxxxxxxxxxx FIGMA_FILE_KEY=AbCdEfGhIjKlMnOp ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxx GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxx CHROMATIC_PROJECT_TOKEN=chroma_xxxxxxxxxx
⚠ Security

Never commit .env.local to version control. Add it to .gitignore. For CI/CD, store each value in GitHub → Settings → Secrets → Actions.

Phase 2 Figma → Storybook

Take designs from Figma and generate production-ready React components with Storybook stories using Claude as the code generator.

2.1

Export design tokens from Figma

Figma Variables API → tokens/figma-raw.json → Style Dictionary

▼

Create scripts/export-tokens.js. This calls the Variables API and writes the raw JSON:

const response = await fetch( `https://api.figma.com/v1/files/${FILE_KEY}/variables/local`, { headers: { 'X-Figma-Token': process.env.FIGMA_TOKEN } } ); const { meta } = await response.json(); fs.writeFileSync('tokens/figma-raw.json', JSON.stringify(meta, null, 2)); console.log(`Exported ${Object.keys(meta.variables).length} variables`);

Then run Style Dictionary to transform tokens into CSS custom properties and JS exports:

npx style-dictionary build # generates dist/tokens.css + dist/tokens.js
💡 Tip

Run this script on a schedule (e.g. every Monday) or hook it to the Figma file-published webhook to keep tokens always fresh.

2.2

Export component specs from Figma

Fetch component metadata, variants, and node styles

▼

Fetch the component index from the Figma REST API:

GET https://api.figma.com/v1/files/:key/components # Each component returns: # name: "Button/Primary/Default" # componentSetId: links to the variant group # description: used as JSDoc comments # key: unique ID for Code Connect

For each component, also fetch its node to get exact computed styles (color values, spacing, font sizes, border radius):

GET https://api.figma.com/v1/files/:key/nodes?ids=:nodeId
⚠ Rate limits

The Figma API allows 150 requests/minute per token. For large files, batch requests in groups of 20 with a 500ms delay between batches.

2.3

Generate components with Claude

Send spec + tokens to Claude API → receive typed React + Stories

▼

Create scripts/generate-component.js. Build the prompt by combining the component spec with your tokens file, then call Claude:

const Anthropic = require('@anthropic-ai/sdk'); const client = new Anthropic(); async function generateComponent(figmaSpec, tokens) { const msg = await client.messages.create({ model: 'claude-sonnet-4-20250514', max_tokens: 4096, system: `You are a design system engineer. Generate clean, typed React components. Use CSS Modules for styling. Follow the project conventions in the provided context.`, messages: [{ role: 'user', content: `Generate a React component for: ${figmaSpec.name} Figma Spec: ${JSON.stringify(figmaSpec)} Design Tokens: ${JSON.stringify(tokens)} Output: 1) Component .tsx 2) Stories .stories.tsx 3) types.ts` }] }); return msg.content[0].text; }
◈ Prompt tip

Include 1–2 existing component files from your codebase in the system prompt. Claude will match your exact patterns for imports, prop naming, and file structure—reducing manual edits significantly.

2.4

Write files and open a Pull Request

Save generated code to the repo · Create a GitHub PR for review

▼

Parse Claude's response to extract each file, write them to the correct directories, then use Octokit to open a PR:

const { Octokit } = require('@octokit/rest'); const octokit = new Octokit({ auth: process.env.GITHUB_TOKEN }); // Write files fs.mkdirSync(`src/components/${name}`, { recursive: true }); fs.writeFileSync(`src/components/${name}/${name}.tsx`, component); fs.writeFileSync(`src/components/${name}/${name}.stories.tsx`, story); fs.writeFileSync(`src/components/${name}/types.ts`, types); // Create PR await octokit.pulls.create({ owner, repo, title: `feat(design-system): add ${name} from Figma`, head: `design-system/${name.toLowerCase()}`, base: 'main', body: `Auto-generated from Figma. Component: ${figmaSpec.key}` });
Phase 3 Storybook → Figma

The reverse direction: when developers update components in code, Claude diffs the changes and updates Figma automatically via a plugin.

3.1

Detect changes in component files

TypeScript AST extraction on every push to main

▼

Create scripts/extract-metadata.js. Use ts-morph to parse component files and extract all props, variants, and style values into a meta.json alongside each component:

const { Project } = require('ts-morph'); const project = new Project(); project.addSourceFilesAtPaths('src/components/**/*.tsx'); for (const file of project.getSourceFiles()) { const props = file.getInterfaces().map(i => ({ name: i.getName(), properties: i.getProperties().map(p => ({ name: p.getName(), type: p.getType().getText() })) })); fs.writeFileSync( file.getDirectoryPath() + '/meta.json', JSON.stringify(props, null, 2) ); }
3.2

Claude generates a Figma update plan

Send old vs new component metadata → receive structured action list

▼

Compare the previous meta.json (from git diff) with the new version and send both to Claude with this prompt:

"Compare these two versions of a React component. Identify all changes that affect the visual design: - New or removed variant values (e.g. new 'size' prop values) - Renamed props that map to Figma variant properties - Updated design token references in styles - Structural changes (new slots, removed elements) Output JSON with this exact shape: { \"actions\": [ { \"type\": \"UPDATE_VARIANT\", \"nodeId\": \"...\", \"newName\": \"...\" }, { \"type\": \"UPDATE_TOKEN\", \"nodeId\": \"...\", \"token\": \"...\" }, { \"type\": \"ADD_VARIANT\", \"componentSetId\": \"...\", \"name\": \"...\" } ] }"
◈ Claude tip

If the token names in your meta.json don't map 1:1 to Figma variable names, include a token alias map in the prompt so Claude can translate correctly.

3.3

Apply updates via Figma Plugin

Lightweight plugin polls sync endpoint and applies actions

▼

Create a Figma plugin that polls your sync endpoint (a small Vercel/Netlify function that stores pending actions) and applies them:

// figma-plugin/code.ts async function applyPendingUpdates() { const res = await fetch('https://your-sync.vercel.app/api/pending'); const { actions } = await res.json(); for (const action of actions) { if (action.type === 'UPDATE_VARIANT') { const node = figma.getNodeById(action.nodeId); if (node) node.name = action.newName; } if (action.type === 'UPDATE_TOKEN') { await applyTokenBinding(action.nodeId, action.token); } } figma.notify(`✓ Synced ${actions.length} updates from Storybook`); await markActionsComplete(actions.map(a => a.id)); } applyPendingUpdates(); // runs on plugin open
💡 Plugin install

In Figma: Plugins → Development → Import plugin from manifest. Point to figma-plugin/manifest.json. Designers run this plugin after any code-side change is merged to main.

Phase 5 Ongoing Maintenance

Keep the system healthy over time: audit for drift, migrate tokens, and coordinate between designers and developers.

5.1

Audit drift with Claude

Find every mismatch between Figma and code on demand

▼

Send both the Figma spec and the React component to Claude with this audit prompt. It returns a structured JSON list of every discrepancy with severity levels:

"Compare the Figma spec and the React component below. List every mismatch as JSON. For each include: - type: color | spacing | variant | typography | missing - figmaValue: what Figma has - codeValue: what the code has - severity: breaking | visual | minor - suggestedFix: one-sentence description of the fix"
5.2

Token migration

Update all components when Figma variable names change

▼

When token names change in Figma (e.g. color.primary → color.brand.primary), use this Claude prompt to update all affected files automatically:

"Token names have changed. Migration map: { \"color.primary\": \"color.brand.primary\", \"spacing.md\": \"spacing.400\" } Update all token references in these component files. Return each file with only token references changed. Do NOT change any component logic or JSX structure."
